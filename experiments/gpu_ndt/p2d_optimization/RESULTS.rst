Lite3 P2D 两项优化交付记录（2026-11-17）
======================================

结论
----

error-only 和实例 GPU 工作区的实验源码均已完成，并通过可执行的离线检查。
目前不能确认 GPU 更快或室外 P95/P99 改善：Jetson SSH 两次超时，本机没有 CUDA
Toolkit，亦缺少 PCL 开发头文件。本轮未部署、未原生编译、未执行 CUDA Kernel。
原始 GPU 实验、正式 CPU NDT、NDT P0/P1、UKF、TF、VOA 和安全期限保持。

修改
----

* B：三个原生源码文件增加 64 行。新增 ``p2d_ndt_compute_error_only`` 标量归约，
  只有 H/b 同时为空时分派；完整导数、Cauchy、协方差和当前对应关系保持原样。
* C：在 B 上两个原生源码文件增加 51 行。实例内持久化搜索/评估位姿缓冲，
  对应关系首次预留、后续沿用原来的扩容策略。原有对应关系容器已经保留 capacity，
  不把它描述为此前每轮必定重新申请。不修改 D2D 数学或 CPU LM。
* CPU/GPU 计算依赖、搜索完成事件和归约完成等待保留；没有直接删除同步调用。
* 工具生成私有 A/B/C 源树和观测基准，保存真实 LM 调用计数、候选误差耗时、
  align 段 CPU 时间、GPU 频率端点及原有资源记录。
* C 的类布局改变，因此私有构建同时重建两份 GPU 动态库、头文件和实验程序，
  封存完整文件哈希，禁止用不匹配的单库替换。

完整增量源码见 ``B_error_only.patch``、``C_workspace.patch``；
阶段性原生构建、Kernel 验证及性能对照命令见 ``README.rst``。

验证边界：

* 真实 .cu 的数学代码和原始 LM 函数体作为主机 C++ 编译运行；Thrust、CUDA API、
  体素构建和对应关系搜索使用明确标记的替身。不是 nvcc 编译或 CUDA 执行。
* 200 组候选误差检查的最大差为 0；五个普通初值、三个冲突观测初值的 A/B/C
  LM 决策序列、调用次数和最终位姿完全相同。冲突观测覆盖多次拒绝和负 rho
  但增量已收敛的分支。这些合成输入不能证明真实扫描或并行归约一致性。
* 预热后 25 轮搜索+完整评估+候选评估，替身记录的显式位姿容器申请：A/B 各 75，
  C 为 0。不是 cudaMalloc 计数；Thrust 内部临时分配仍待 Nsight 检查。
* 一个完整 benchmark 的 C++ 语法检查因缺少 PCL 开发头文件跳过。
  生成的 CUDA 包装器已分别用 std/boost 指针及 CUDA API 替身编译检查。
* 主机内存检查不等于 GPU 内存/异步检查；后者需恢复连接后运行 compute-sanitizer。
* Python 语法检查和 ``git diff --check`` 通过。
