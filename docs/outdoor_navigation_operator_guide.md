# Lite3 室外导航自主操作说明

适用项目：`/home/duyipei/Lite3_Projects/lite3_patrol_project`

本说明基于 2026-09-29 已成功执行的短距离 A–B 导航流程。所有下列 Shell 命令均在 **Ubuntu 虚拟机终端**执行，不是在 Jetson 的 SSH 终端执行。

## 1. 使用范围与安全要求

- 雷达/导航地图：`outdoor_20260921_003_area_review`。
- 视觉地图：`outdoor_20260921_003`。
- 相机：原有相机1；本说明不涉及相机2。
- Jetson：`ysc@192.168.1.103`，使用项目现有 SSH 密钥连接。
- 已验证：起点外观候选 → NDT 雷达确认 → 路径规划 → 实际运动 → Nav2 返回成功。
- 尚不能保证任意地点视觉重定位成功；优先在原建图起点附近、相近朝向初始化。
- 此次成功不是视觉 PnP 成功：使用的是起点外观候选加 NDT 确认。
- 当前最大前进速度为 `0.15 m/s`，到达位置容差为 `0.35 m`，朝向容差较宽；不能视为精确位置/朝向停靠。

> 全程手持官方遥控器并准备急停。紧急情况优先使用遥控器，不要等待网络命令响应。不要绕过定位检查、速度门或避障机制。

## 2. 开始前的必要准备

1. 确认虚拟机与机器狗网络已连接，机器狗电量足够。
2. 将机器狗放在原建图起点附近，朝向尽量与建图时一致。
3. 确认相机1插紧、视野无遮挡，初始化期间机器狗保持静止。
4. 使用官方遥控器确认机器狗处于厂商允许的可行走状态。
5. 清空目标路径附近的人员与障碍，首个目标只选择附近 1–2 米。

不需要额外运行一遍完整预检查；下面的 `start` 已包含必要检查。

## 3. 从头启动：终端 A

打开虚拟机终端，执行：

```bash
cd /home/duyipei/Lite3_Projects/lite3_patrol_project

LITE3_VISUAL_MAP_ID=outdoor_20260921_003 \
LITE3_VISUAL_SEARCH_STRATEGY=startup_then_global \
bash scripts/indoor_nav_start.sh start outdoor_20260921_003_area_review
```

说明：

- 脚本虽然叫 `indoor_nav_start.sh`，但以上命令明确选择的是已验证的室外地图。
- 必须填写室外地图和视觉库，不能直接使用脚本的默认室内配置。
- 脚本会同步运行脚本和配置，检查相机、启动定位与 RViz，再检查完整 Nav2 负载下定位连续稳定 30 秒。
- 脚本不会自动解锁运动。
- 保持终端 A 打开；不要重复启动第二套导航。

等待出现：

```text
NAVIGATION READY（默认不会运动）
导航控制>
```

**只有启动全部通过后才能继续。** RViz 画面上的位置看似稳定，不等于定位数据时效检查通过。

### 如果导航已经在运行

不要再次执行 `start`。在另一个终端查看状态：

```bash
cd /home/duyipei/Lite3_Projects/lite3_patrol_project
bash scripts/indoor_nav_start.sh status outdoor_20260921_003_area_review
```

确认实时定位就绪、速度门锁定后，使用现有 RViz。若状态命令提示只能查看历史日志，不能把历史日志当作解锁依据。

## 4. 在 RViz 设置目标

1. 确认地图、点云、机器狗的位置和方向与现场相符。
2. 点击工具栏 **2D Goal Pose**。
3. 在附近白色可通行区域点击并拖动，选择目标位置与方向。
4. 只发送一次目标，等待预览路径出现。
5. 确认路径不穿墙、不贴近障碍，现场确实可通行。

> 不要点击 `2D Pose Estimate`；本流程通过视觉与 NDT 初始化，不需要手工覆盖位姿。使用启动脚本打开的 RViz，其目标话题已配置为 `/patrol/goal_request`。

## 5. 解锁并执行目标

回到终端 A，在 `导航控制>` 后输入：

```text
ARM
```

看到再次确认提示后，再输入：

```text
ARM
```

确认解锁成功后，机器狗开始执行已排队的目标。

运动中同时观察：

- 机器狗确实朝目标前进，没有异常姿态或方向。
- RViz 定位随实际运动变化，没有跳变。
- 路径和周围环境仍然安全。
- 终端没有定位失效、速度门故障或导航失败。

**有速度输出但机器狗不动，不算成功。** 不要持续重复解锁或提高速度；先锁定，再检查运动状态和链路。

## 6. 到达、下一个目标与退出

### 到达后锁定

确认终端报告 `[NAV DONE]` 或 `SUCCEEDED`，并观察机器狗已停止。随后在终端 A 输入：

```text
DISARM
```

**重要：常规启动脚本在到达后仍保持 ARMED 零速待命，不会自动锁定。** 保持 ARMED 时，下一次 RViz 点选目标会直接执行。此前助手的单次执行监控额外做了自动 DISARM，不能把该行为当成常规脚本默认行为。

初次自行操作建议每次都按以下顺序：

```text
锁定状态下点选目标 → 检查路径 → ARM → 到达 → DISARM
```

### 中途取消

在终端 A 输入：

```text
CANCEL
```

该命令会请求锁定并取消目标。网络无响应或发生危险时，优先遥控急停。

### 完全退出

在终端 A 输入：

```text
QUIT
```

脚本会锁定并清理本次启动的节点。正常结束优先使用 `QUIT`，不要直接关闭虚拟机或拔网线。

## 7. 终端 B：备用操作命令

另开一个虚拟机终端，先执行：

```bash
cd /home/duyipei/Lite3_Projects/lite3_patrol_project
```

### 查看状态

```bash
bash scripts/indoor_nav_start.sh status outdoor_20260921_003_area_review
```

### 解锁已在 RViz 设置的目标

```bash
bash scripts/indoor_nav_start.sh arm outdoor_20260921_003_area_review
```

按提示输入一次 `ARM` 确认。这是终端 A 交互解锁的替代方式，不必两边重复执行。检查服务响应是否成功，不能仅凭命令退出就判断已解锁。

### 锁定、停止当前运动

```bash
bash scripts/indoor_nav_start.sh disarm outdoor_20260921_003_area_review
```

### 停止整套导航

```bash
bash scripts/indoor_nav_start.sh stop outdoor_20260921_003_area_review
```

优先在终端 A 用 `QUIT` 正常退出；终端 A 不可用时可用上述 `stop`。需要重新启动时，先确认旧会话已结束，不要叠加运行。

## 8. 常见异常

| 现象 | 处理 |
| --- | --- |
| 相机没有实时帧 | 不解锁，检查相机线缆、服务与图像流；服务在线不代表有图像 |
| `no_pnp_solution`、视觉超时 | 不强行通过；检查是否位于已采集起点附近、朝向是否合适、视野是否遮挡 |
| NDT 未确认、`odometry_stale`、定位 FAILED | 保持锁定，结束会话；排查后重新初始化，不能只清速度门故障 |
| 有速度但无位移 | DISARM，确认官方遥控器状态和运动主机链路；不要提高速度强行尝试 |
| 定位跳动、运动方向异常、路径不安全 | 遥控急停，随后 DISARM，停止本次测试 |
| 网络断开 | 遥控停止；恢复后查看实时状态，不默认沿用断连前的就绪状态 |
| 目标被取消 | 先查原因并恢复就绪；在锁定状态下重新点选目标，再确认解锁 |

`CLEAR` 只清速度门的锁存故障，不能修好视觉/NDT，也不能作为反复绕过故障的操作。

## 9. 保留本次成功配置

本次针对定位计算延迟的修复包括：

- 用精确批量最近邻查询降低评分成本，并与原算法结果比对。
- 对不变地图去重，避免每秒重复构建 NDT/最近邻索引。
- 限制定位进程 OpenMP 忙等待，保留原匹配与安全阈值。
- 日志持久化，并修复启动过程中中断后继续执行的问题。

实测完整负载下处理频率约 8–9.5 Hz，额外两分钟审计最大有效里程计间隔 0.495 秒，低于原有 0.70 秒门限。该结果是当次现场验证，不保证后续每次环境都相同。

**启动脚本不会自动编译或恢复 C++ 定位补丁。** 正常使用当前修复后的 Jetson 不必每次编译；若重装、替换或重新编译底层定位程序，需要确保保留此修复版。也不要把这次单条短路径成功当作全地图避障或长时间运行验收。

启动终端会打印本次日志目录，位于项目 `logs/` 下。失败时保留日志，不要删除后反复盲目重试。
