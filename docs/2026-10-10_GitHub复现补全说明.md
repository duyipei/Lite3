## 在新环境中的恢复顺序与已知缺口

1. 先恢复匹配的原厂系统、驱动、Nav2/STVL 和运动桥，再核对传感器话题。
2. 将完整项目放在预期路径，配置自己的 SSH 认证。
3. 在 Jetson 编译本次保存的 Livox SDK2、Sophus 1.22.10 及建图工作空间。
   当前编译缓存为 Release，`CMAKE_PREFIX_PATH` 指向项目 `fast_livo2_ws/deps_install`。
   上游 README 示例以 Humble 为主，不要原样替换现有 Foxy 环境。
   编译前按需要创建 `src/FAST-LIVO2/Log/PCD` 等运行输出目录，下载中未保留旧运行输出。
4. 对照原厂基础版本应用 `vendor_patch/hdl_localization_app.hpp` 和入口源码差异，
   在 Jetson 重新编译定位包。先备份，不能在定位进程运行时覆盖程序。
5. 编译 `patrol_nav_ws` 到脚本预期的 `install_merged`。
   **已知缺口：** `setup.py` 尚未登记 `map_display.launch.py`，应在首次构建前
   将它加入 launch 的 `data_files`；只执行现有 colcon build 并不能完全安装全部启动文件。
6. 同步地图 YAML、实际引用 PGM、PCD、视觉数据库、配置与源码。
   `indoor_nav_start.sh install/start` 只是现有环境的增量同步，不是全新环境安装器，
   不会替你完整安装依赖、建立所有源码目录或首次传输所有地图资产。
7. 离线测试后再进行现场 preflight、静止定位、DISARMED 检查，最后单独授权低速测试。

本次只做备份补全与说明，没有在干净 Jetson 上重建/编译，不能称为一键复现已完成。
