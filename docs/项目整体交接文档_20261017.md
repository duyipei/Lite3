## 1. 项目简介与交接结论

项目基于云深处绝影 **Lite3 激光版机器狗**，目标是在校园室内外完成环境采集、地图生成、初始重定位、低速自主导航与多点巡航，并为后续巡检识别任务提供移动平台。

当前主线是 **激光雷达与 IMU 建图（LIO）+ RGB-D 视觉建库 + 视觉初始位姿 + NDT/腿部里程计持续定位 + Nav2 导航**。项目控制机体速度，不控制腿部关节，也不替换原厂步态系统。

交接时最重要的事实：

- 已有室内、室外点云地图、二维导航地图和视觉数据库。
- 单点 A–B 导航有实机成功记录；多点调度已实现，并有前 10 点到达的历史记录，但整条 11 点路线尚未完成验收。
- 默认视觉模式为 ORB，可使用 LoFTR 备用匹配；新增 XFeat + LighterGlue + PnP 可选模式，不能称为已经通过现场鲁棒性验证。
- 运动依赖显式 ARM，定位守卫和速度门独立工作。
- 最新启动优化取消了 Nav2 启动后的第二次视觉初始化；完成离线测试，尚无证据证明修改后完整实机启动流程通过。
- 工程依赖原厂驱动、Nav2/STVL、运动桥和 Jetson 环境，复制项目目录不等于在空白设备上完成部署。

## 4. 系统架构和接口

```text
采集 / 建图路径
Mid360 + IMU + D435i → 同批次 rosbag
  ├─ LiDAR + IMU 派生 bag → FAST-LIVO2 的 LIO 模式 → 点云 + 轨迹
  ├─ RGB-D + 轨迹 → 视觉关键帧数据库
  └─ 雷达观测 + 轨迹 → 二维可通行栅格图

在线导航路径
相机 → ORB（可选 LoFTR）或 XFeat + LighterGlue
     → PnP / 受限起点外观候选 → 视觉初始化守卫 → /initialpose
激光雷达 + IMU + 腿部里程计 → 修正后的 hdl_localization / NDT
     → /odom、TF、/status → 初始化确认与持续就绪守卫
RViz / 多点执行器 → 隔离目标桥 → Nav2 → /patrol/cmd_vel_raw
     → 默认 DISARMED 的速度门 → /cmd_vel_corrected
     → 原厂 motion_sender → UDP → 运动主机
```

| 接口 | 用途 |
| --- | --- |
| `/camera/color/image_raw`、`/camera/depth/image_rect_raw` | 相机1彩色与深度 |
| `/camera/color/camera_info` | 相机标定信息 |
| `/front_camera/image_raw` | 相机2视频桥接图像 |

| `/odom`、`/aligned_points`、`/status` | 定位输出、对齐点云、NDT 匹配状态 |

## 7. 视觉初始重定位

### 7.1 ORB 路线（默认）

读取旧库参考照片、ORB 描述子、像素位置、三维点与关键帧地图位姿；对实时图像提取 ORB，进行候选检索、匹配和 PnP 几何验证。连续视觉样本通过后注入粗位姿，再由 NDT 独立确认。

可选 LoFTR 是 ORB 匹配困难时的本机备用匹配路径。日志来源需区别：

| 来源 | 含义 |
| --- | --- |
| `source=pnp` | ORB 对应的几何解 |
| `source=learned_pnp` | LoFTR 备用匹配后的 PnP |
| `source=start_appearance` | 受限起点外观候选，不是 PnP 成功 |
| `source=xfeat_lighterglue_pnp` | XFeat/LighterGlue 对应的 PnP |

起点外观候选不证明机器人已在任意位置实现全局视觉定位，仍须 NDT 和后续守卫确认。

### 7.2 XFeat 路线（可选）

设置 `LITE3_VISUAL_BACKEND=xfeat_lighterglue`。当前从旧库照片重新提取 XFeat，再用 LighterGlue 匹配；没有将 ORB 描述子转换成 XFeat，也不在该模式中回退 ORB、LoFTR 或起点外观先验。

由于原始 RGB-D 不完整，当前三维对应借用旧 ORB 点的稀疏深度：参考 XFeat 点在 6 像素内找旧深度，优先局部逆深度拟合，剔除混合前后景和重复对应，再反投影。新特征有二维匹配不代表能获得可靠三维点。

因此当前是“新的图像匹配算法 + 旧稀疏地图几何”的实验接入，不是完整原生 XFeat 地图库。参考照片相同位置自匹配成功不能证明跨视角、跨光照定位鲁棒性。

## 8. NDT、腿部里程计和初始化守卫

在线定位使用适配后的原厂 `hdl_localization` / NDT，不应把早期原厂 Faster-LIO 建图基线误称为当前项目建图算法。

`visual_pose_initializer.py` 负责视觉帧/时间/协方差、样本稳定性、地图转换、NDT 匹配和腿部里程计确认，并发布定位就绪。定位 READY 后继续检查 NDT 状态、腿部里程计、定位里程计的新鲜度及跳变等。NDT READY 是系统检查结果，不是外部真值精度认证。

当前室内正式配置的关键值：10 个视觉样本、稳定时长 4 秒、样本最大间隔 2.5 秒、15 次 NDT 确认、NDT 最大匹配误差 0.15。应以实际地图 YAML 为准，勿将一个地图的阈值套用到全部地图。

静止 `relocalize` 模式使用独立测试配置：6 次视觉采样、10 次 NDT 确认，并要求 READY 保持 10 秒；不启动 Nav2 和速度门，不改变正式导航配置。

历史 NDT 实时性修复包括：限制 OpenMP 忙等待、增加阶段耗时、以精确批量最近邻降低评分开销、忽略内容未变的重复全局地图以避免重复建索引。源码在 `vendor_patch/`；新设备复现时不能只拿上游包替换本地适配版。

当前启动脚本默认 NDT 分辨率为 1.0 m，默认下采样 0.3 m，指定现有室外地图时下采样为 0.5 m；运行前核对是否被环境变量覆盖。历史文档中的 0.5/0.2 等配置不代表当前默认。

## 9. 导航、巡航与运动门控

### 9.1 导航系统

Nav2 使用 NavFn 全局规划、DWB 局部控制及原厂 STVL 等组件。全局路径只是规划结果，不是底盘运动轨迹或到达证明。默认控制链将 Nav2 输出隔离到 `/patrol/cmd_vel_raw`，由项目速度门决定是否输出到原厂运动链路。

速度门默认 DISARMED；检查定位、里程计、雷达心跳、命令时效及输出竞争。常见上限为前进 0.15 m/s、角速度 0.40 rad/s，实际使用地图与运行参数为准。原厂 VOA 属于可选独立路径，不能与项目速度门竞争真实运动输出，也不能把原厂运动桥随意停止。

用户只要求最终朝向与目标一致，允许途中倒车。当前室内配置验收位置约 0.35 m、朝向 0.10 rad；室外历史终点修正仍为 0.35 m / 0.20 rad，不能混称为所有地图统一阈值。

### 9.2 多点任务

默认室外任务为 `navigation/outdoor_20260921_003_area_review/mission_recovered_20261008.yaml`，包含 11 个点，坐标来自历史 SVG 矢量图恢复。

任务保存 `mission_version`、`map_id`、`frame_id`、地图 YAML/图像哈希，以及每点的 `id/x/y/yaw/pause_s`。当前仍标记 `enabled: false`、`review_required: true`；入口可经现场 ARM 授权执行草稿，但不会将草稿改写为已认证路线。

执行器逐点发送目标，默认单点超时 120 秒，包含任务心跳、取消/停止、低速转向无进展保护；失败不自动重新解锁，全部完成后锁定。运行中不要另外发送 RViz 目标造成任务竞争。

`preflight` 包含运行文件增量同步和检查，不是纯本地只读命令；不启动导航运动。新设备上它不负责首次安装全部依赖或传输全部大地图资产。


### 10.4 单点导航

```bash
LITE3_VISUAL_BACKEND=orb \
bash scripts/navigation_start.sh start indoor_fusion_20260912_001_area_review

LITE3_VISUAL_BACKEND=xfeat_lighterglue \
bash scripts/navigation_start.sh start outdoor_20260921_003_area_review
```

等待 `NAVIGATION READY`，核对 RViz 地图、位姿和现场一致，通过 RViz 隔离目标入口设置目标；按交互终端提示 ARM。当前终端支持 `STATUS / CLEAR / ARM / DISARM / CANCEL / QUIT`。

也可在另一个终端执行 `bash scripts/navigation_start.sh arm 地图ID`，但 `start` 不会自动执行整条巡航。它持续占用终端，因此不能简单用 `start && arm` 实现一键衔接。

### 10.5 多点巡航

保持导航终端运行，另一个已配置无线地址的终端执行：

```bash

  outdoor_20260921_003_area_review mission_recovered_20261008.yaml

bash scripts/patrol_route.sh run \
  outdoor_20260921_003_area_review mission_recovered_20261008.yaml
```

`check` 离线校验，`run` 需要明确 ARM 授权并实际连接机器人；一次授权不代表路线通过验收。

### 10.6 状态与停止

```bash
bash scripts/navigation_start.sh status 地图ID
bash scripts/navigation_start.sh disarm 地图ID
bash scripts/navigation_start.sh stop 地图ID
```

实际运动异常时以原厂遥控停止手段为优先，不依赖网络命令一定及时送达。定位失败需检查并重新初始化，不能靠 CLEAR 或反复 ARM 绕过。
