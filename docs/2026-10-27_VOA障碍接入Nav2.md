# VOA 障碍接入 Nav2（2026-10-27）

## 状态与目的

本机代码已修改并完成离线验证；用户确认机器狗当前无法连接，本次未部署、未启动机器人运动。解决的接口缺口是：相机/VOA 检测到的实体障碍原来只影响速度输出，Nav2 没有对应障碍观测，可能一直给出被 VOA 拦停的路线。

修改后，动态导航模式的数据流为：

```text
深度相机 → 厂家点云处理与 VOA elevation 栅格
                         ├→ VOA 同轨迹减速/停车 → 速度门 → 底盘
                         └→ voa_costmap_bridge.py
                             → /patrol/voa/costmap_obstacles
                             → 全局、局部代价地图的 voa_obstacle_layer
                             → Navfn 重规划 + DWB 选择可通行轨迹
```

雷达、静态地图继续参与规划。VOA 不自行改变方向。原始 ORB/XFeat 初始重定位、NDT+里程计、目标朝向要求、速度上限不变。只有动态导航入口启用新桥接。

## 实现与坐标约定

- `scripts/voa_costmap_bridge.py` 订阅 `/patrol/voa/grid_map`，读取 `elevation`，使用 `navigation/vendor_voa.yaml` 的 `kObstatleHeight`（当前 0.10 m），与 VOA 相同地选择有限且严格大于阈值的栅格。没有另设一个不同的障碍高度阈值。
- 解码 GridMap 的矩阵行/列存储方式、数据偏移和循环缓冲索引。它不是 OccupancyGrid，直接按普通图片行列转换会镜像/转置障碍。
- 厂家 VOA 已对相机点云做 IMU 横滚/俯仰补偿和 0.34751 m 足端高度平移；当前 `vendor_patch/hdl_localization_app.hpp` 对 NDT 输入使用同一处理。NDT 发布的历史名称 `map -> base_link` 实际承载该注册参考系的位姿。桥接使用这个注册变换一次，不重复施加相机安装变换、足端高度或室内参考补偿。
- 按栅格原始采样时刻查询 NDT TF，完整应用旋转和平移，包括室内参考修正产生的俯仰；之后保留地图 X/Y、将输出 Z 设为 0.5 m。输出只用于二维代价地图标记，不能送回 VOA 或用于三维投影/标定。
- 栅格与当前 NDT TF 都使用 Jetson 的 monotonic 传感器时间域。桥接保留源时间戳，不改成墙上时间。源数据超过 0.5 秒或提前超过 0.05 秒不接受；重复/倒序帧不刷新健康状态。查询不到采样时刻 TF 就等待/丢弃，不用最新位姿替代。
- 10 Hz 发布上限；保留最多 16 帧，选最新且有匹配 TF 的帧，避免 10 Hz NDT 与更快相机之间的等待饥饿。字段/尺寸异常会使进程退出，并由启动监督器停掉私有 VOA，速度门随后锁定停车。

若以后修改 NDT 注册参考系、时钟、厂家 VOA 坐标处理或替换厂商版本，必须重新核对上述契约。当前实现没有给 `robot_foot_print` 添加虚假的静态 TF。

GridMap 坐标与消息约定参考 [GridMap ROS 转换器](https://github.com/ANYbotics/grid_map/blob/ros2/grid_map_ros/src/GridMapRosConverter.cpp)、[矩阵消息布局](https://github.com/ANYbotics/grid_map/blob/ros2/grid_map_ros/include/grid_map_ros/GridMapMsgHelpers.hpp) 和 [索引到坐标转换](https://github.com/ANYbotics/grid_map/blob/ros2/grid_map_core/src/GridMapMath.cpp)。

## 代价地图与故障行为

`make_dynamic_nav2_config.py` 给全局、局部地图各增加一个 STVL 层 `voa_obstacle_layer`，位于膨胀层之前：

| 参数 | 本次设置与作用 |
|---|---|
| 输入 | `/patrol/voa/costmap_obstacles`，PointCloud2 |
| sensor_frame | `base_link`，距离从实时注册位置计算，不从地图原点计算 |
| voxel_size | 0.05 m，保留相机栅格尺度 |
| voxel_decay | 1.5 s，线性消退，长于当前全局 1 Hz 更新间隔 |
| observation_persistence | 0，处理后清空观测缓存，不重复灌入旧障碍 |
| expected_update_rate | 0.5 s，与源数据时效一致 |
| combination_method | max，与已有雷达/静态层取最大值 |
| marking / clearing | true / false，不用相机射线清掉静态墙体或雷达障碍 |
| 高度过滤 | 0.4–0.6 m，仅接纳桥接产生的合成 Z=0.5 |

障碍离开后，新栅格不再标记它，历史体素随时间消退；实际显示还包含代价地图更新周期。新鲜的零障碍帧仍发布空点云及健康信号。源中断时不发送伪造的空帧证明通路安全。

动态模式速度门新增 `require_voa_costmap=true`：必须持续收到带原始采样时间戳的 `/patrol/voa/costmap_heartbeat`。源年龄超过 0.5 秒、桥接未就绪或输出发布者冲突，拒绝 ARM；运动中发生则零速并锁存故障。恢复数据不会自动重新 ARM。非动态模式默认不要求此链路。

STVL 的输入变换、观测缓存和更新时间语义依据 [Foxy measurement_buffer.cpp](https://github.com/SteveMacenski/spatio_temporal_voxel_layer/blob/foxy-devel/src/measurement_buffer.cpp)。桥接健康证明点云已转换并发布；是否被 Jetson 上两个实际 STVL 层消费仍需要在线验收。

## 离线验证及边界

测试结果：72 项 unittest 回归通过，另 1 项原生 C++ VOA 减速选择器测试通过；真实 ROS PointCloud2 的空帧/障碍帧序列化通过，室内与室外动态配置均生成成功。日志：`logs/voa_nav2_bridge_offline_20261027.txt`。

测试覆盖：非对称栅格位置、行列存储、循环索引、数据偏移、地图平移/旋转/室内俯仰、NaN/Inf、空点云、源过期/重放、TF 未到达、实际 PointCloud2 序列化、子进程失败清理、桥接失效停车和故障不可自动解锁。动态配置测试验证两个代价地图均接入、基线地图不被修改、原雷达地面过滤保持原行为。

`tests/test_voa_navfn_offline.py` 调用虚拟机已安装的 **Galactic 原生 NavFn 库**，用真实桥接转换得到的障碍构造测试代价地图：无障碍直行、只有相机障碍时绕行、障碍移除恢复、完全封堵时无路径均通过。这里的栅格标记与膨胀是测试夹具；不是 Jetson Foxy STVL/DWB 的完整集成实测，也没有验证运动后避障性能。

NaN/Inf 未观测区域不被捏造成实体墙或清障观测，VOA 仍会对未知区域实施保护。因此未知空间、狭窄通道、定位漂移、无可行转向轨迹依然可能停车。此修改提供反应式障碍绕行的数据基础，不包含行人轨迹预测；不能宣称已完成行人/车辆动态避让验收。

## 连接恢复后的使用与验收

原动态导航命令不变，启动时自动同步新 Python 文件、速度门和启动器，并在 Jetson 生成新 `nav2_dynamic.yaml`。已有私有 VOA 构建产物可复用，本次无需重编译厂家 C++。

```bash
cd /home/duyipei/Lite3_Projects/lite3_patrol_project
unset ROBOT
export LITE3_ROBOT_HOST=10.119.1.171
export LITE3_VISUAL_BACKEND=orb
export LITE3_VISUAL_SEARCH_STRATEGY=global
bash scripts/navigation_dynamic.sh start indoor_fusion_20260912_001_area_review
```

先保持 DISARMED。`velocity_gate.log` 应出现 `[VOA_COSTMAP] first fresh projection published` 和 `[VOA_COSTMAP] fresh obstacle projection received`。日志每 5 秒输出栅格数量、障碍数量与未知数量，或等待栅格/TF 的状态。

在线验收顺序：

1. 放置相机可见的静止障碍，检查投影点云、两个实时 costmap 的障碍位置与现场一致。注意仅有发布心跳不足以证明 STVL 已消费。
2. 确认全局规划绕过障碍、DWB 局部轨迹有足迹余量；不要用仍保留的 RViz 旧预览路径证明当前规划成功。此前 `/plan` 预览/实时显示 QoS 问题不在本次改动范围内。
3. 移走障碍，验证两个动态层在消退及更新后释放位置，静态墙体继续保留。
4. 受控低速测试单个目标绕行，再运行多点巡航。无可行绕行空间应停止等待，而非强行通过。
5. 停掉桥接或相机数据，确认拒绝 ARM 或锁存停车；数据恢复后不得自动解锁。

仅检查本机生成配置：

```bash
bash scripts/navigation_dynamic.sh check indoor_fusion_20260912_001_area_review
bash scripts/navigation_dynamic.sh check outdoor_20260921_003_area_review
```
